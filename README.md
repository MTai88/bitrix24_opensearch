# mtai.opensearch — морфологический поиск по Bitrix24 через OpenSearch

Модуль заменяет штатный поиск CRM (`crm.api.entity.search`, выпадающая
подсказка в шапке портала) полнотекстовым морфологическим поиском во
внешнем OpenSearch: «Ивану» находит «Иван», «потенциальной сделке» —
«Потенциальная сделка», «Копейке» — «ООО Копейка».

## Возможности

- **Морфология русского и английского** — встроенные анализаторы Lucene
  `russian`/`english` (стеммер + стоп-слова), без внешних плагинов.
- **Область поиска настраивается в админике**:
  - CRM-сущности: лиды, сделки, контакты, компании;
  - смарт-процессы — выбор конкретных процессов по названию (включая
    смарт-счета), у каждого свои поля;
  - пользователи портала (ФИО, должность, отдел, email, телефоны);
  - инфоблоки — выбор конкретных инфоблоков; у каждого свои поля
    элементов (название, анонс, детальное описание, теги), **свойства**
    элементов и, отдельно, **разделы** с их полями (название, описание
    и UF-поля раздела).
- **Поля каждой сущности выбираются individually** (select multiple):
  системные поля, **пользовательские поля UF_** CRM-сущностей и
  смарт-процессов, свойства и UF-поля разделов инфоблоков. Изменение
  набора полей применяется сразу и не требует переиндексации: у каждого
  типа сущности в запросе — своя ветка со своими полями.
- **Поиск по телефону и email** — телефоны нормализуются до цифр,
  email — до нижнего регистра.
- **Совместимый контракт ответа** — экшен `mtai:opensearch.api.entity.search`
  возвращает данные в том же формате, что и `crm.api.entity.search`
  (`{items, limits}`, элементы `Bitrix\Main\Search\ResultItem`), поэтому
  шапка портала, выбор клиента в карточках CRM и прочие потребители
  работают без изменений. CRM-элементы форматируются штатными адаптерами
  CRM — ссылки, подзаголовки, телефоны/email в выдаче идентичны штатному
  поиску.
- **Права доступа** — CRM-элементы фильтруются штатной проверкой прав
  (`Crm\Service\UserPermissions`), элементы инфоблоков — правами
  инфоблока (`CIBlockRights`).
- **Живая индексация** — обработчики событий CRM/пользователей/инфоблоков
  обновляют индекс сразу при изменении; агент раз в 5 минут
  переиндексирует пропущенное (массовые операции, импорт).
- **Отказоустойчивость** — если OpenSearch недоступен, JS-патч молча
  откатывается на штатный поиск: портал продолжает работать.
- **Полный переиндекс с прогрессом** — страница обслуживания в админке
  и CLI-скрипт.

## Как устроена замена штатного поиска

Штатный экшен `crm.api.entity.search` резолвится в
`Bitrix\Crm\Controller\Entity` ядром, и подменить его класс серверно
нельзя. Поэтому модуль подключает на страницах лёгкий JS-патч
(`/bitrix/js/mtai.opensearch/patch.js`, вставляется перед `</body>`
через событие `OnEndBufferContent`):

1. Оборачивает `BX.ajax.runAction`: вызовы `crm.api.entity.search`
   перенаправляются на `mtai:opensearch.api.entity.search` с теми же
   параметрами.
2. Если экшен вернул ошибку (OpenSearch недоступен), выполняется
   оригинальный штатный запрос — прозрачный фолбэк.
3. Пользователи и элементы инфоблоков (которые фронтенд шапки не умеет
   рендерить в CRM-блоках) дописываются патчем в подсказку: блок
   «Сотрудники» заменяет штатный LIKE-блок, инфоблоки выводятся
   отдельными секциями.

## Требования

- Bitrix24 / Битрикс: Управление сайтом с модулем CRM (тестировалось
  на 26.750.0, PHP 8.3);
- OpenSearch 2.x/3.x, доступный по HTTP из PHP (без зависимостей
  composer — используется `Bitrix\Main\Web\HttpClient`).

## Установка

1. Скопируйте модуль в `local/modules/mtai.opensearch`.
2. Установите модуль в админке: Настройки → Настройки модулей →
   `mtai.opensearch` (или через CLI, см. ниже).
3. В настройках укажите хост/порт OpenSearch и нажмите
   «Проверить соединение».
4. Выберите область поиска (CRM-сущности, пользователи, инфоблоки).
5. Запустите полный переиндекс: страница «Обслуживание индекса
   OpenSearch» в админке (Настройки → OpenSearch) или CLI-скрипт.

### OpenSearch в docker compose

```yaml
services:
  opensearch:
    image: opensearchproject/opensearch:3.2.0
    restart: unless-stopped
    environment:
      - discovery.type=single-node
      - DISABLE_SECURITY_PLUGIN=true   # только для внутренней docker-сети!
      - OPENSEARCH_JAVA_OPTS=-Xms512m -Xmx512m
    volumes:
      - opensearch_data:/usr/share/opensearch/data

  # опционально: веб-интерфейс для отладки запросов
  opensearch-dashboards:
    image: opensearchproject/opensearch-dashboards:3.2.0
    environment:
      OPENSEARCH_HOSTS: '["http://opensearch:9200"]'
      DISABLE_SECURITY_DASHBOARDS_PLUGIN: "true"
    ports:
      - "5601:5601"
```

Для продакшена включите security-плагин и HTTPS.

### CLI-переиндекс

```bash
docker compose exec php php /var/www/html/local/modules/mtai.opensearch/cli/reindex.php          # с пересозданием индекса
docker compose exec php php /var/www/html/local/modules/mtai.opensearch/cli/reindex.php --keep   # поверх существующего
```

## Схема индекса

Один индекс (по умолчанию `bitrix24_morpho`), `_id = <entity_type>_<id>`:

| Поле         | Тип      | Назначение                                       |
|--------------|----------|--------------------------------------------------|
| entity_type  | keyword  | crm_lead / crm_deal / … / user / iblock          |
| crm_type_id  | long     | CCrmOwnerType::* для CRM-элементов               |
| entity_id    | long     | ID сущности                                      |
| category_id  | long     | воронки (сделки, смарт-процессы)                 |
| iblock_id    | long     | для элементов инфоблоков                         |
| title        | text     | заголовок, анализаторы morpho_ru + .en + .raw    |
| subtitle     | text     | должность/компания/название инфоблока            |
| fields       | object   | отдельные поля сущности (comments, post, preview, content, …); подволя создаются динамически с морфологией |
| phones       | keyword  | нормализованные телефоны (только цифры)          |
| emails       | keyword  | email в нижнем регистре                          |
| url          | keyword  | ссылка на карточку                               |
| attrs        | object   | данные для отрисовки (email, фото, …), не индексируется |
| date_update  | date     | время обновления документа                       |

## Точки расширения

Модуль публикует события ядра (`Bitrix\Main\Event`, модуль-источник
`mtai.opensearch`). Без подписчиков поведение не меняется. На них
опирается `mtai.aisearch` (гибридный поиск и AI-ответ в шапке).

| Событие | Где | Параметры | Что может обработчик |
|---------|-----|-----------|----------------------|
| `onSearchHits` | `SearchService::search` после BM25 и до проверки прав | `query`, `entityTypes`, `iblockIds`, `categoryId`, `userId`, `hits` | Вернуть `EventResult::SUCCESS` с `['hits' => [...]]` — новый порядок хитов (элементы с `_id` и `_source`, как в ответе `_search`). Пустой результат или исключение оставляют исходную выдачу BM25. Событие вызывается и когда BM25 ничего не нашёл. |
| `onAfterIndexDocument` | точечная запись, шаг переиндекса и инкрементальная синхронизация — после успешного bulk/index | `id`, `document` | Например, поставить документ в очередь эмбеддингов. |
| `onAfterDeleteDocument` | после успешного удаления документа | `id`, `document` (`null`) | Убрать вектор этого документа. |

## Ограничения

- Смарт-процессы индексируются полным переиндексом и живыми событиями
  не покрываются (нет надёжных событий на изменение их элементов).
- Изменения телефонов/email в карточке CRM не всегда порождают событие
  обновления сущности — такие правки доедут в индекс при ближайшем
  полном переиндексе.
- Свойства инфоблоков типов «привязка к элементу/разделу» индексируются
  как ID (не названием); списки и текстовые — человекочитаемо.
- Встроенный стеммер `russian` по-разному обрабатывает некоторые слова
  (фамилии на «-ов»: «Кузнецов» → «кузнец», но «Кузнецову» → «кузнецов»)
  — отдельные формы могут не находиться.
- Права на пользователей не фильтруются по видимости (как и в штатном
  поиске сотрудников): ищутся все активные сотрудники портала.
- В подсказке шапки заменяется блок «Сотрудники» и CRM-блоки; поиск
  Disk и Задач остаётся штатным.
